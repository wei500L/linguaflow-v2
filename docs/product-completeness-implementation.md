## 迁移

`apps/api/drizzle/0012_product_completeness_round.sql` 只加表和可空/有默认值的列。`0013_note_citation_snapshot.sql` 给笔记版本补上输入哈希、输出语言和引用快照。`0014_summary_attempt_gap_merge.sql` 给额度账本补上请求编号，给笔记版本补上引用是否可验证。旧字幕仍可阅读。已经开着且未撤销的听众链接会把 `audience_keep_after` 设为 true。新会话默认关闭。

降级不能只删新表。旧 API 不认识 `deleted_at`，降级后回收站记录会重新出现在普通列表。降级前要先停写，导出 `note_versions`、`support_requests` 和未过期回收站，并准备让旧版本继续隐藏 `deleted_at is not null` 的记录。不要在生产库上手动清数据。先在隔离库演练。

崩溃点的本机断言：

| 场景 | 模型调用 | 账本 |
| --- | --- | --- |
| 额度已占用、模型尚未返回时杀进程 | 0 | 60 秒仍为 held，没有结算 |
| 同一确认在重启后重放 | 1 | 这 60 秒变为 settled，没有第二笔 |
| 本次输出已持久化、待办修复仍失败 | 不再增加 | 新的 60 秒保持 held，旧笔记不被换成这次结果 |
| 失败解除后再次重启 | 不再增加 | 这 60 秒结算，正文和待办是这次的版本 |
| 完成事务提交前杀进程 | 1 | 新的 60 秒仍 held，页面上的旧正文保持原样 |
| 重启后重放这次确认 | 0 | 新的 60 秒结算，正文换成这次输出 |
| 提交后、客户端尚未看到成功时杀进程，再重放 | 0 | 结算总额不变，确认返回 ready 且 duplicate |
